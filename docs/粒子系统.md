# 粒子系统

粒子发射器既是 ECS 里的一份组件，也是一条独立的渲染通道。模拟在 CPU 上确定性完成，
渲染端把存活粒子展开成朝向摄像机的公告板，用加色混合叠加到当帧画面上。

## 三分钟示例

```cpp
#include <Concord/CParticle.h>
#include <Concord/CScene.h>

Concord::Scene scene;
scene.Spawn<Concord::Object::ParticleEmitter>({
    .transform = {.position = {0.0f, 0.2f, 0.0f}},
    .settings  = {.shape        = Concord::ParticleShape::Cone,
                  .shapeExtent  = {0.4f, 0.15f, 0.0f},   // 半径、高度
                  .emissionRate = 320.0f,
                  .lifetime     = {1.1f, 1.9f},
                  .speed        = {1.4f, 3.2f},
                  .startSize    = {0.18f, 0.34f},
                  .endSize      = {0.02f, 0.07f},
                  .spreadDegrees = 30.0f,
                  .gravity      = {0.0f, 2.4f, 0.0f},
                  .drag         = 0.9f,
                  .startColor   = COLOR_RGB(255, 198, 96),
                  .endColor     = COLOR_RGBA(176, 26, 8, 0),
                  .capacity     = 2048}});

game.Systems().Add<Concord::ParticleSystem>();   // 必须注册，否则池不会推进
game.LoadScene(scene);
```

`Transform` 决定发射器的位置和朝向：`direction` 与锥体都定义在发射器局部空间里，
所以把发射器转个角度，火焰就会朝新的方向喷。

## 模拟模型

`ParticleSystem` 每帧对 `ParticleEmitterComponent + Transform` 查询一次，调用
`StepParticleEmitter`，顺序固定为**先发射、再积分、最后回收**：

1. **发射** —— 起始帧按 `burstCount` 一次性喷发；随后每帧按
   `emissionRate × deltaTime` 累加欠账，小数部分跨帧保留，因此低速率发射器的节奏
   不会随帧率抖动。
2. **积分** —— `v = v / (1 + drag·dt) + gravity·dt`，再推进位置。阻尼用隐式形式，
   所以 `drag` 取多大都不会让速度发散或反向。
3. **回收** —— `age >= lifetime` 的粒子被最后一个存活粒子交换覆盖，存活区间始终连续，
   渲染端可以直接线性遍历。池只分配一次，运行期不产生新分配。

单步时长被限制在 `kMaxParticleStepSeconds`（0.1 秒）以内。掉帧时粒子会"变慢"
而不是一步穿越整个生命周期，这是有意的稳定性取舍。

## 空间语义

| `localSpace` | 粒子坐标 | 发射瞬间 | 发射器之后移动时 |
|---|---|---|---|
| `true`（默认） | 发射器局部空间 | 记下局部偏移 | 粒子跟着发射器走 |
| `false` | 世界空间 | 用发射器矩阵烘焙到世界 | 粒子留在原地 |

`gravity` 始终按**世界空间**书写。对局部空间的发射器，系统会用发射器矩阵的逆向刚体
变换把重力旋进局部坐标系，所以把一个发射器翻过来，粒子仍然朝世界的下方落，而不是
朝发射器自己的"地板"落。

## 确定性

每个发射器自带一个 xorshift 生成器，种子来自 `settings.seed`。相同种子加相同的
`deltaTime` 序列会得到逐位相同的粒子位置，这一点由
`tests/ParticleSimulationTests.cpp` 的 "same seed replays identically" 用例锁住，
可以直接用于录像回放或网络同步的验证。

## 渲染路径

1. `ExtractRenderScene` 在提取快照时调用 `AppendParticleSnapshots`，把每个发射器的
   存活粒子展开成世界空间的三角形（每粒子 6 个顶点）。
2. 公告板的 right/up 轴直接取自当帧摄像机视图矩阵的两行，因此不需要逐粒子的着色器
   参数，也不需要实例化绘制。
3. `RecordVulkanParticlePass` 上传顶点并录制一次绘制：**加载**已有的颜色和深度附件，
   深度测试开、深度写关，混合因子为 `(ONE, ONE)`。

加色混合带来一个直接好处：**结果与绘制顺序无关**，所以粒子完全不需要排序。代价是
粒子只能发光、不能遮挡，颜色向量的 alpha 通道起的是强度作用（`endColor` 的 alpha
写 0 就是淡出）。片段着色器用解析衰减画圆形柔边，不依赖任何贴图。

几何量上限是 `kMaxRenderedParticles`（8192 个粒子），超出的发射器会被跳过而不是
让缓冲区无限增长。粒子通道不新增任何描述符集：它复用帧数据布局（set 0）拿摄像机
矩阵，和分块光源裁剪的计算通道用的是同一份布局。
