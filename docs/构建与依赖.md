# 构建与依赖

## concord/ 完全自包含

```
concord/
├── CMakeLists.txt          # 引擎工程，定义两个 DLL target
├── cmake/
│   ├── ConcordDependencies.cmake  # 定位第三方导入库，暴露打包辅助函数
│   └── ConcordSources.cmake       # 按 DLL 分组的源文件清单
├── include/
│   ├── Concord/            # 门面头（用户唯一入口）
│   └── engine/             # 模块私有头（真实声明）
├── src/
│   ├── engine/             # 与 include/engine 镜像的实现
│   └── 3rd/                # 第三方头文件（SDL3/Vulkan/SteamAudio/stb）
├── lib/                    # 预编译库（.lib/.dll/.a）
├── assets/                 # logo、图标等品牌资源
├── docs/                   # 本目录
└── LICENSE                 # MPL-2.0
```

根目录只放注册用的宿主工程：一个最小的 `CMakeLists.txt`
（`add_subdirectory(concord)` + 一个消费引擎的可执行文件）和 `main.cpp`。
这个边界是有意的：`concord/` 可以被复制到任何项目里直接
`add_subdirectory`，不依赖仓库根目录的任何东西。

## 两个引擎 target

```cmake
add_library(concord::runtime ...)  # ConcordFlashGameEngineRuntime.dll
add_library(concord::render  ...)  # ConcordFlashGameEngineRender.dll
add_library(concord::concord INTERFACE)  # 链接两者的便捷别名
target_link_libraries(concord::concord INTERFACE concord::runtime concord::render)
```

消费方只需要：

```cmake
target_link_libraries(my_game PRIVATE concord::concord)
```

## 第三方依赖：headers 在 src/3rd，库在 lib

| 库 | 版本 | 头文件位置 | 库文件位置 | 用途 |
|---|---|---|---|---|
| SDL3 | 3.4.14 (MinGW) | `src/3rd/SDL3` | `lib/SDL3.dll`, `lib/libSDL3.dll.a` | 窗口与输入（不参与渲染） |
| Vulkan | 1.4.357 (仅头文件) | `src/3rd/Vulkan` | `lib/vulkan-1.lib` | 渲染 API |
| Steam Audio | 4.8.1 | `src/3rd/SteamAudio` | `lib/phonon.dll`, `lib/phonon.lib` | 空间音频（规划中） |
| stb | master | `src/3rd/stb` | 纯头文件，无需链接 | 图像/字体加载（规划中） |

运行仓库根目录的 `setup_deps.ps1` 会下载并安装以上全部依赖，可重复执行。
`ConcordDependencies.cmake` 里的 `concord_find_implib` 会在多个候选文件名
之间自动探测（MSVC 用 `SDL3.lib`，MinGW 用 `libSDL3.dll.a`），因此同一套
`lib/` 目录在两种工具链下都能配置成功。

## 打包成可分发产物

```sh
./package_bin.ps1
```

产出的 `bin/` 是一个可以直接压缩分发的独立目录：可执行文件、两个引擎
DLL、第三方运行时 DLL（`SDL3.dll`、`phonon.dll`）、MinGW 运行时三件套
（`libgcc_s_seh-1.dll`/`libstdc++-6.dll`/`libwinpthread-1.dll`，仅
MinGW 构建需要），以及供运行期写入的 `Assets/Config/Data/Logs/Scenes`
目录——这一层结构直接对应第一代 `bin/` 的布局。`bin/` 和 `build/` 一样
是生成产物，不进版本控制。

## 为什么静态导入库要按工具链探测

`SDL3.lib`（MSVC 风格）和 `libSDL3.dll.a`（MinGW 风格）是同一个
`SDL3.dll` 的两种导入库格式，彼此不能互换链接器。`vulkan-1.lib` 同理有
两种形式。`ConcordDependencies.cmake` 按候选名单探测，是为了让同一份
`concord/` 目录既能被 MSVC 项目使用，也能被本机默认的 MinGW/Ninja 工具链
使用，而不需要用户手动区分。
