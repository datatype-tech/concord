# 应用与窗口

## Game：唯一的生命周期入口

`Game` 拥有至多一个窗口和一个激活场景，并驱动把两者连起来的帧循环。

```cpp
Concord::Game game;
Concord::Window window({.title = "My Game"});
game.AttachWindow(window);   // 真正打开 OS 窗口，并按需初始化渲染器

Concord::Scene scene;
game.LoadScene(scene);       // 激活场景：其中的实体开始被渲染和调度

game.Run();                  // 阻塞运行，直到窗口被关闭
```

- `AttachWindow` 之前，`Window` 只是一份描述（`WindowDesc`），不对应任何
  真实的 OS 窗口。
- 渲染器是否初始化取决于 `GameConfig::enableRendering`（默认开启）；关闭时
  `Game` 仍会打开窗口、驱动帧循环和系统调度，只是不提交任何 GPU 工作——
  适合无头测试或纯逻辑模拟。
- `Run()` 内部顺序固定：轮询窗口事件 → 调用 `OnUpdate` 回调 →
  `SystemSchedule::Update` → 渲染一帧。改变这个顺序需要修改 `Game::Run`
  本身，而不是在调用方拼凑。

## Window：描述与活动句柄的双重身份

`Window` 在 `AttachWindow` 前后是同一个对象，但语义不同：

| 状态 | `Set()` 的效果 |
|---|---|
| 未附加 | 只更新本地描述，不产生任何可见变化 |
| 已附加 | 更新描述，并把改动实时推送到已打开的 OS 窗口 |

```cpp
window.SetTitle("加载中...");
window.SetMode(Concord::WindowMode::Borderless);
```

`WindowDesc` 是纯聚合体，`Set()` 整体替换描述——没写的字段取
`WindowDesc` 的默认值，而不是窗口的当前值。想保留某个字段就要先从
`window.Desc()` 里复制。

## SDL3 只管窗口和输入

窗口创建、事件轮询、显示模式切换全部由 SDL3 承担，但这一层完全被
`Window` 的 pimpl 挡住：公开头 `Window.h` 不会带出 `SDL3/SDL.h`。
SDL3 从不参与渲染——表面创建之后，渲染帧的每一步都是纯 Vulkan 调用。
