# 着色器工具链

Concord 的 Vulkan 着色器源文件位于 `assets/shaders/`。源文件随引擎版本
管理，编译产物永远写入构建树，不会污染源码目录：

```
assets/shaders/mesh.vert   -> <build>/shaders/mesh.vert.spv
assets/shaders/solid.frag  -> <build>/shaders/solid.frag.spv
assets/shaders/tile_cull.comp -> <build>/shaders/tile_cull.comp.spv
assets/shaders/directional_shadow.vert -> <build>/shaders/directional_shadow.vert.spv
```

## 可选编译

默认配置不要求开发机安装 shader 编译器：

```sh
cmake -S . -B build -G Ninja
```

需要编译时显式打开选项：

```sh
cmake -S . -B build -G Ninja -DCONCORD_BUILD_SHADERS=ON
```

CMake 优先使用 `CONCORD_SHADER_COMPILER` 指定的可执行文件，否则在
`PATH` 中探测 `glslc`、`glslangValidator` 或 `dxc`。没有找到工具时只打印警告，
`concord_shaders` 变为空目标，Runtime/Render 和测试仍可正常构建。当前
编译命令固定 Vulkan 1.3 目标环境，并按源文件名和 stage 后缀生成稳定路径。

ConcordScript 生成的 `ConcordScriptShaders.cmake` 同样使用这套 helper。
默认情况下，外部 `file=` shader 相对于生成目录解析；项目可以在 include
生成片段前设置 `CONCORDSCRIPT_EXTERNAL_SHADER_ROOT`，或在 CMake cache 中
覆盖它。对 GLSL 自定义入口，`glslangValidator` 会同时传递 `-e` 与
`--source-entrypoint main`，因此能保持源码入口和 SPIR-V 入口一致；HLSL
则由 `-e` 直接选择源码函数。HLSL 可使用
`glslangValidator` 或支持 SPIR-V 后端的 DXC；引擎内置 shader 全部是 GLSL，
指定仅支持 HLSL 的 DXC 时会跳过内置 shader 编译并给出警告。

## 运行时 staging

调用 `concord_stage_runtime(target)` 会让目标依赖 `concord_shaders`，并把
可用的 `.spv` 文件复制到：

```
<target-directory>/Assets/Shaders/
```

因此发布运行时优先读取分发目录中的文件，不依赖开发机的构建树；开发调试
时也允许从当前目录的 `assets/shaders/` 回退。编译器缺失时不会复制半成品；真正创建 Vulkan `VkShaderModule` 前，
后续 loader 应检查文件可读、字节数为 4 的倍数以及 SPIR-V magic
`0x07230203`，失败时报告 shader 名称和 stage。

## 当前接口约定

`mesh.vert` 是 depth-only 和 forward 管线共用的最小顶点 fixture：

- 顶点位置由 `gl_VertexIndex` 从 36 个 unit-box 三角形顶点中生成；
- 不需要 vertex buffer；场景数据通过 set 0 / binding 0 的 `FrameDataBlock`
  UBO 提供；
- 每个 Box 的 push constant 为固定 96-byte 块，包含 `mat4 model`、线性
  `albedo` 和 `metallic/roughness/emissive`；
- `FrameDataBlock` 使用 std140-compatible 的 16-byte 对齐布局，包含相机、
  环境光和最多 64 个方向/点/聚光灯记录；当前 `solid.frag` 对方向光执行
  最小 Lambert + 高光模型，并从 binding 1 的 tile light-list SSBO 读取可见
  光源。`tile_cull.comp` 使用同一 frame descriptor，在固定 16×16 tile 上生成
  每 tile 最多 64 个索引；完整 tile 资源或 shader 不可用时由 CPU 标志关闭 tile
  路径，fragment shader 回退遍历完整 light 数组。即使完整 SSBO 分配失败，
  descriptor binding 1 仍绑定最小占位 buffer，以保持同一 pipeline layout 有效。

`tile_cull.comp` 与 `solid.frag` 共用 set 0：binding 0 是 frame UBO，binding 1
是 tile light-list SSBO；这两个 binding 必须保持一致，且 tile flag 必须在 UBO
上传前写入。

方向光阴影的基础资源使用独立 descriptor set：binding 0 是带比较采样器的深度
图像，目标布局为 `VK_IMAGE_LAYOUT_DEPTH_STENCIL_READ_ONLY_OPTIMAL`。写入端使用
`directional_shadow.vert` 的 128-byte push constant（light view-projection 与
object model），通过单独的 depth-only dynamic-rendering pipeline 生成深度。
资源按 frame slot 分配，避免多帧并行时覆盖仍在采样的 shadow image；前向 shader
尚未读取该 set，资源或 shader 不可用时现有 tile/clear 路径保持不变。

后续实现 staging buffer 和更精确的深度分层裁剪时，应继续显式声明 set/binding
和结构体布局；不要依赖编译器自动分配 binding。shader 编译器版本应在
CI/发布环境固定，以避免同一源文件产生不可追踪的接口变化。
