# 模型导入与骨骼动画

`<Concord/CModel.h>` 提供统一的 CPU 侧模型入口：

```cpp
const Concord::ModelLoadResult result =
    Concord::ModelLoader::Load("Assets/character.gltf");
if (!result.Succeeded()) {
    // result.ErrorMessage()、result.error.line、result.error.column
}
```

支持 `.obj`、`.gltf` 和 `.glb`。OBJ 支持负索引、三角扇、多对象/分组、MTL
基础色/粗糙度和漫反射纹理引用；导入选项可以翻转 V 坐标、缩放模型，并为缺失
法线和切线生成稳定的几何值。glTF 使用内置 JSON 解码器，不依赖外部运行库，支持
data URI、外部 buffer、PBR 基础色/金属度/粗糙度、自定义节点 TRS、索引/非索引三角形、
skin、inverse-bind 矩阵和动画。

## 骨骼动画

`Skeleton::CreateBindPose()` 生成绑定姿势；`SampleAnimation()` 从绑定姿势开始采样
translation、rotation 和 scale 通道，支持 STEP、LINEAR、CUBICSPLINE。动画播放可以
交给 `AnimationPlayer`：

```cpp
Concord::SkeletonPose pose = skeleton.CreateBindPose();
Concord::AnimationPlayer player;
player.Play(asset.FindAnimation("Walk"));
player.Update(skeleton, deltaSeconds, pose);
```

`pose.jointMatrices` 是 `globalJoint * inverseBind` 的矩阵，可直接上传到 skinning
buffer。`SampleClipIntoPose()` 是采样入口的显式形式，与 `SampleAnimation()` 行为一致。

## 动画混合、状态机与层

在单 clip 采样之上，`engine/animation` 提供完整的混合栈（详见
[动画混合与状态机.md](动画混合与状态机.md)）：

- `BlendPoses()` / `AdditiveBlendPose()`：逐关节 crossfade 与加法混合，
  旋转走四元数 Slerp，缺失关节回退绑定姿势。
- `AnimationGraph`：状态与转移的不可变描述（clip、速度、循环、exit time），
  构建时校验索引与参数。
- `AnimationStateMachineState` + `EvaluateAnimationStateMachine()`：运行时求值，
  处理请求式切换、exit-time 自动转移、非循环结束与过渡期双 clip 权重混合。
- `JointMask` / `MaskSubtree()` / `MaskJoints()`：逐关节权重遮罩，可按子树或
  关节名生成。
- `AnimationControllerComponent`：ECS 组件，持有一个基础图与最多 4 个
  Override/Additive 层；`AnimationSystem` 会优先求值 controller，输出仍写入
  `SkinningPoseComponent`，渲染管线无需感知混合。`AnimationSystem` 可作为普通 ECS system 注册，逐帧推进 `AnimationComponent`，
并更新配套的 `SkinningPoseComponent`。缓存 pose 的 `sourceAsset` 必须指向产生它的同一
`ModelAsset`，这样资源切换时不会把旧 palette 误用于新模型。动画组件只保存非 owning 的
`ModelAsset*`，资产必须由 `ModelRenderer` 的共享指针或其他外部所有者保持存活；采样过程
不修改模型资产本身。导入器会拒绝越界索引、循环骨架、无序关键帧、非有限浮点值和结构不完整的资源。

## Mixamo 人形工作流

Mixamo 角色与动画经 Blender 转换后进入引擎：Mixamo 导出 FBX → Blender 导入并
导出 glTF/GLB（勾选 Animation + Skinning）→ `ModelLoader::Load()`。引擎侧的
对应支持：

**单位与缩放**：`ModelLoadOptions::scale` 会一致地作用于顶点位置、节点平移、
动画 translation 关键帧（含 CUBICSPLINE 切线）和 inverse-bind 平移列，因此
Mixamo 常见的厘米单位（Blender 导出 0.01 缩放）用 `scale = 0.01f` 即可整体
换算，蒙皮与根位移保持一致。

**rig-only 资源**：只有骨架与动画、没有网格的 GLB（如"Skeleton Only"下载）
可以导入，用作动画源；渲染侧从它得不到任何 draw。

**命名与识别**：`NormalizeJointName()` 会剥离 `mixamorig:`/`Armature|` 前缀并
归一分隔符与尾数字（`Spine_01` → `spine1`）；`BuildHumanoidSkeleton()` 据此把
骨架映射到语义槽（Hips/Spine/Head/四肢等），`IsValid()` 要求 Hips、Spine、
左右 Arm 与左右 UpLeg 齐备。

**跨骨架重定向**（`engine/animation/AnimationRetarget.h`）：

```cpp
const Concord::HumanoidSkeleton sourceHumanoid =
    Concord::BuildHumanoidSkeleton(sourceAsset.skeletons[0]);
const Concord::HumanoidSkeleton targetHumanoid =
    Concord::BuildHumanoidSkeleton(targetAsset.skeletons[0]);

Concord::RetargetOptions options{.rootMotion = Concord::RootMotionMode::ExtractRootMotion};
Concord::RetargetResult result;
if (Concord::RetargetClip(sourceHumanoid, *sourceClip, targetHumanoid, options, result)) {
    targetAsset.animations.push_back(std::move(result.clip));
    if (result.hasRootMotion) {
        targetAsset.animations.push_back(std::move(result.rootMotion));  // "*_RootMotion"
    }
}
```

重定向按语义槽改写通道的目标关节（采样器零改动），旋转直接拷贝；Hips 平移按
"骨架链长度比"（Hips→Head 与 Hips→双脚的均值）缩放，使位移匹配目标体型。三种
根运动模式：`KeepBaked`（原样，原地播放即原地动画）、`InPlace`（剔除水平位移、
保留垂直）、`ExtractRootMotion`（额外产出仅含 Hips 平移与旋转的根运动 clip，
供游戏逻辑驱动 Transform）。重定向产物 append 到目标 asset 后，可直接交给
[动画混合与状态机](动画混合与状态机.md) 的 `AnimationGraph` 使用。

**strict 导入的额外拒绝**（`ModelLoadOptions::strict`，默认开启）：镜像矩阵
（行列式 < 0 的 node matrix）、只带 JOINTS_0/WEIGHTS_0 之一的蒙皮网格、以及
所有通道都解析不到任何骨架的动画 clip；非 strict 模式分别降级为去除旋转、
默认权重与丢弃 clip。

## Vulkan 静态网格上传

场景实例只需持有一个共享的不可变资产：

```cpp
auto asset = std::make_shared<Concord::ModelAsset>(result.asset);
scene.Spawn<Concord::Object::Model>({.asset = asset});
```

若资产含有节点，快照会为每个带 mesh 的节点生成 draw；`meshIndex` 可限制为单个
mesh。动画系统则由调用方显式注册：

```cpp
game.Systems().Add<Concord::AnimationSystem>();
```

Render DLL 提供内部 `VulkanModelAsset` 资源。`BuildVulkanModelUpload()` 先把多 mesh、
多 primitive 展平成稳定的顶点/索引数组，并产生 `VulkanModelPrimitiveRange`；每个范围
保留材质索引和原 mesh 索引。`CreateVulkanModelAsset()` 再使用持久映射的
`VulkanBuffer` 上传 vertex、index 和 std430-compatible material buffer，失败时会回收
已经创建的部分资源。材质的 base color 在上传前转换为线性空间；图片 URI 由 stb 解码为
RGBA8，Render DLL 为每个 frame slot 维护上传、布局转换和 fallback 白纹理，模型的
base-color sampler 在 forward pass 中按 primitive 绑定。

`Object::Model` 会把模型实例放入场景快照；Render DLL 在首次可见时缓存并上传其静态
vertex/index/material buffer，使用独立的 indexed depth/forward pipeline 绘制。节点父子
变换会在快照阶段展开，避免多个 glTF 部件重叠到实体原点。静态模型现在也会进入方向光
shadow map：每个 primitive 按原 mesh 过滤并复用节点世界变换；缺少专用资源时安全回退。
GPU skinning 已使用每帧 palette SSBO 和独立的 skinned depth/forward pipeline，蒙皮模型
也能投射方向光阴影。具备 AS/BDA 能力时，静态模型 primitive 还会为每个 frame slot
懒创建 BLAS 并加入 TLAS，供 ray-query 遮挡使用；完整 primary RT 在命中 shader 取得
模型法线/材质前仍保守回退到光栅路径。GLB `image.bufferView` 已转换为受限 MIME-aware
data URI 并复用同一图片缓存；GPU-local staging、normal/metallic-roughness 纹理和
蒙皮模型 RT 仍是后续切片。
