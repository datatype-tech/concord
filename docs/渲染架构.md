# 渲染架构

## 两个 DLL，一个单向依赖

| DLL | 内容 | 依赖 |
|---|---|---|
| `ConcordFlashGameEngineRuntime.dll` | `app`/`ecs`/`scene`/`window` | 仅 SDL3 |
| `ConcordFlashGameEngineRender.dll` | Vulkan 后端（`render/` 全部） | Runtime（取 `Window` 原生句柄）、SDL3、Vulkan |

这个划分复刻了第一代按模块拆 DLL 的思路（`CEngine.dll`/`CAudio.dll`/...），
但只拆成两个：渲染后端体量大、迭代快，值得独立；其余模块耦合紧密
（`Game` 同时拥有 `Window`、`Scene`、`SystemSchedule`），拆开反而增加
不必要的 DLL 边界。

### 打破循环依赖：自注册工厂

`Game::AttachWindow` 需要构造一个渲染后端，但 `Game` 所在的 Runtime.dll
绝不能 `#include` 具体的 `VulkanRenderBackend.h`——那会让 Runtime 反过来
依赖 Render，和 Render 依赖 Runtime 的方向冲突，形成循环。

解决办法是 `RenderBackendFactory`：

```cpp
// engine/render/RenderBackendFactory.h（Runtime.dll，只认识接口）
using CreateRenderBackendFn = std::unique_ptr<IRenderBackend> (*)();
void RegisterRenderBackend(CreateRenderBackendFn factory);
std::unique_ptr<IRenderBackend> CreateRenderBackend();
```

应用代码在构造第一个 `Game` 之前显式调用：

```cpp
Concord::LinkVulkanRenderBackend();  // 定义在 Render.dll，触发它注册自己
Concord::Game game;                 // Game 内部只调用 CreateRenderBackend()
```

这个链接调用是**显式的函数调用，不是静态初始化器**——加载顺序应该是
读者能在代码里看到的东西，而不是靠 DLL 静态构造函数的隐式顺序去猜。

## Forward+ 路线图

目标管线：深度预通道 → 光源分块裁剪 → 前向着色。当前地基阶段完成的部分：

- ✅ 实例 / 物理设备选择（优先独显）/ 逻辑设备（启用 dynamic rendering）
- ✅ SDL 表面创建，与 Window 的唯一交汇点
- ✅ 交换链创建与按窗口尺寸变化重建
- ✅ 双缓冲帧同步（`MAX_FRAMES_IN_FLIGHT = 2`），每帧独立命令缓冲/信号量/栅栏
- ✅ dynamic rendering 清屏通道（按场景 `EnvironmentSettings::skyColor`）
- ⬜ 深度预通道
- ⬜ 光源分块裁剪
- ⬜ 前向着色管线与材质系统对接
- ⬜ 阴影贴图

## 帧生命周期

```
Init(window, enableValidation)
  -> [ BeginFrame() -> DrawScene(scene) -> EndFrame() ] 重复
  -> Shutdown()
```

`BeginFrame` 负责：检测窗口尺寸变化并重建交换链、等待栅栏、获取下一张
可呈现图像、开启命令缓冲。`DrawScene` 目前只做清屏（下一步接管线）。
`EndFrame` 提交命令缓冲并呈现，呈现结果为"过期/次优"时会重建交换链。

## 校验层

Debug 构建默认尝试启用 `VK_LAYER_KHRONOS_validation`；未安装时静默跳过
（`VulkanContext::validationEnabled` 记录实际结果，不会因为校验层缺失而
让初始化失败）。Release 构建里 `Game::AttachWindow` 强制关闭校验层。

## Vulkan 子模块划分

`render/vulkan/` 下每个文件对应帧生命周期的一个独立职责：

| 文件 | 职责 |
|---|---|
| `VulkanContext` | 贯穿始终的句柄集合（instance/device/queue/...） |
| `VulkanInstance` | 实例创建，请求 SDL 所需扩展和校验层 |
| `VulkanPhysicalDevice` | 队列族查找、物理设备优选 |
| `VulkanDevice` | 逻辑设备创建，启用 dynamic rendering |
| `VulkanSurface` | `SDL_Vulkan_CreateSurface`，SDL 与 Vulkan 的唯一交界 |
| `VulkanSurfaceFormat` | 表面格式与呈现模式选择 |
| `VulkanSwapchain` | 交换链、图像视图、per-image 信号量 |
| `VulkanFrameSync` | 命令池、per-frame 命令缓冲/信号量/栅栏 |
| `VulkanImageBarrier` | 图像布局转换（undefined → 附件 → 呈现） |
| `VulkanClearPass` | dynamic rendering 清屏通道 |
| `VulkanPresent` | 提交队列与呈现 |
| `VulkanBackendRegistration` | 向 `RenderBackendFactory` 注册自己 |

每个文件不超过 150 行，只做一件事——这是仓库级别的硬约束（见 AGENTS.md）。
