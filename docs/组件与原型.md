# 组件与原型

## 内置组件

| 组件 | 字段要点 | 用途 |
|---|---|---|
| `Transform` | `position`/`rotation`(欧拉角,度)/`scale` | 几乎每个实体都有 |
| `MeshRenderer` | `shape`/`size`/`visible`/`castShadow` | 标记可绘制并指定内置几何体 |
| `Material` | `albedo`/`metallic`/`roughness`/`emissive` | 表面外观，金属-粗糙度工作流 |
| `CameraComponent` | `target`/`up`/`fovYDegrees`/`priority` | 配合 `Transform` 构成摄像机 |
| `LightComponent` | `type`/`color`/`intensity`/`elevationDegrees`/`azimuthDegrees` | 方向光/点光/聚光的统一表示 |
| `Name` | `value` | 调试用的可读标签 |

组件**都是纯聚合体**：没有构造函数、没有虚函数、不含行为。任何逻辑都
应该写成系统（见[系统与调度.md](系统与调度.md)），而不是塞进组件的成员函数。

## 自定义组件

组件不需要注册，直接定义一个结构体就能用：

```cpp
struct Health {
    float current = 100.0f;
    float max = 100.0f;
};

entity.Add<Health>({.current = 50.0f});
scene.Query<Health>([](Concord::Entity e, Health& hp) {
    if (hp.current <= 0.0f) { /* ... */ }
});
```

第一次对某个类型调用 `Add`/`Query` 时，`World` 会按需创建对应的稀疏集
存储——不需要任何注册表或宏。

## 原型是配方，不是容器

一个"可生成类型"（如 `Object::Box`）本身**不持有任何状态**，它只声明：

```cpp
struct Box {
    using Desc = BoxDesc;

    static void Build(World& world, Entity entity, const BoxDesc& desc)
    {
        world.Add<Transform>(entity, desc.transform);
        world.Add<MeshRenderer>(entity, MeshRenderer{.size = desc.size});
        world.Add<Material>(entity, desc.material);
    }
};
```

- `using Desc = ...` 让 `Scene::Spawn<Box>` 能推导出参数类型，调用处
  只需要写花括号：`scene.Spawn<Object::Box>({...})`。
- `Build` 是唯一的职责：把 `Desc` 翻译成一组组件挂到实体上。
  它不注册到任何全局表，不通知渲染器——渲染器和其他系统单纯靠
  `Query` 发现新实体。

## 新增一个原型

1. 在 `engine/scene/` 下新建头文件，定义 `XxxDesc`（聚合体，每个字段带
   默认值）和 `Xxx`（只含 `using Desc` 和 `static Build`）。
2. 在 `Concord/CObject.h`（或对应门面头）里加一行 `#include`。
3. 完成——不需要修改 `Scene`、`World` 或渲染器的任何代码。

这是相对第一代的简化之一：第一代每加一个图元都要同时定义 Desc 结构体和
一个持有状态的 Node 类；这里 Desc 依然存在，但 Node 变成了零状态的配方。
